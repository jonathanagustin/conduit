# Apollo evidence and compatibility notes

This folder progressively discloses the evidence behind Apollo-alignment
claims. Keep the repository-wide `AGENTS.md` rules in force.

- Record source dates, hashes, and bounded observations; do not commit source
  documentation, demo media, extracted frames, or credentials.
- Every upstream page fetched during implementation must leave a durable trace
  in `reference/`: update its review ledger and the narrow topic note with the
  derived contract, ambiguity, and implementation/test consequence. Terminal
  output alone is not evidence.
- Keep public-documentation coverage, local-demo evidence, and implemented
  conformance tests distinct. One is not evidence for another.
- Say `Apollo-aligned` for reconstructed semantics. Say `Apollo-compatible`
  only for a named public format/version backed by a conformance test. Never
  claim compatibility with private Hub/Agent protocols.
- Update `PUBLIC-DOCUMENTATION-COVERAGE.md` when evidence changes an
  implementation status. `Implemented` requires an automated repository test.
- Prefer links to the canonical note over copying an evidence summary into a
  consuming product repository.
