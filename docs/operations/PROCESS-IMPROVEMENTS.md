# Process improvements

Method changes move through `PROPOSED`, `TRIAL`, and `ADOPTED`, or close as
`REJECTED` or `SUPERSEDED`. Adoption requires a recorded measure and a whole-
system cost check. Votes are observations, not adoption evidence.

| PDR | Change | Status | Exit criterion | Measure | Holistic check | Votes |

| P1 | Keep living documentation separate from immutable evidence and machine ledgers. | TRIAL | Three substantial changes finish with zero references to retired living documents and no unexplained evidence mutations. | Baseline: this curation reduced `docs/` from 217 to 132 files, replaced 20 architecture narratives with 9 current documents, removed 66 evaluator-run files, and left zero references to deleted paths. The independent review found one 697-line plan mislabeled as evidence; the follow-up removed it and retained one bounded observation. | Review lookup cost, repository size, provenance, and the risk of deleting unique evidence. | good×0; bad×1 |
| P2 | Accept generated console assets only after the Linux production-build comparison passes. | TRIAL | Three console-affecting changes finish with `scripts/test-console.sh` reporting a byte-identical embedded bundle. | The first cross-platform build produced 13 differing asset paths; regenerating under Linux reduced the mismatch to zero and the gate passed with 28 unit and 77 browser tests. | Linux verification adds runtime and a browser cache, but prevents platform-specific bytes from entering the embedded production bundle. | good×1; bad×0 |
| P3 | Do not spend manual CI minutes while any aggregate local gate is known to fail, even when the failure predates the candidate diff. | TRIAL | Three manual-CI candidates either reach zero aggregate failures locally or record no paid dispatch. | The first application prevented one knowingly failing dispatch and converted three baseline failures into an executable repair slice. | This delays merge when trunk already drifted, but restores the gate instead of normalizing or hiding a broken baseline. | good×1; bad×0 |
| P4 | A manual workflow must publish a protected commit status for the authenticated pull-request head. | TRIAL | Three manual Trunk runs produce a PR-visible final status that matches the workflow result and exact head SHA. | Baseline: one 23-gate successful `workflow_dispatch` run produced zero PR-rollup contexts, so branch protection still blocked the merge. The status bridge and its structural test were added before retry. | Two status API calls add little runtime and preserve manual-only execution while making branch protection enforceable. | good×1; bad×0 |

| P5 | Test error precedence when replacing an HTTP boundary with generated parsing. | TRIAL | Three generated-boundary migrations retain authentication and authorization status before payload diagnostics. | The first Apollo generator integration changed four unauthenticated POST cases from `401` to `400`; the focused Linux suite found all four before commit. | The negative-path assertions add negligible runtime and prevent a generated decoder from becoming an unauthenticated protocol oracle. | good×0; bad×0 |
| P6 | Make architecture gates reject the obsolete path, not only require the new path. | TRIAL | Three context extractions prove both the intended dependency and an executable planted-control rejection of the former bridge or backedge. | The Apollo slice removed one request-capture bridge and 463 net production lines from `internal/controlplane`; the gate now rejects both `invokeApolloFacade` and any `internal/apollo` import of `internal/controlplane`. | Two negative string/import checks add negligible runtime and prevent a parallel legacy path from satisfying a presence-only gate. | good×1; bad×0 |
| P7 | Verify cache offload by deleting the volatile targets and lifetime marker, not by checking live symlinks. | TRIAL | Three offload changes pass a simulated wipe and retry test before use in a Codespace. | A real restart exposed four failures hidden by live-link inspection: missing Go module, Go build, and Helm targets plus a mise approved-root mismatch. The new gate wipes state and repairs six cache classes, and two hook installs produce one block. | The fixture adds seconds and temporary directories but never touches live caches; it tests recovery without making durable data disposable. | good×1; bad×0 |

| P8 | Exercise runtime configuration through independent producer and consumer validators using the same positive fixtures and adversarial field mutations. | TRIAL | Three runtime-contract changes keep server, browser, and deployment schemas aligned and reject at least one planted field accepted by any drifted validator. | The first application runs 2 shared tenant fixtures through Go and TypeScript validators and adds 17 negative cases for unknown, executable, unproven, or security-sensitive values; the Helm schema is a third admission layer and the Hub revalidates its output. | Duplicate validators increase maintenance, but the browser cannot trust the server blindly and the Hub cannot delegate startup safety to JavaScript; shared fixtures bound drift without adding a runtime dependency. | good×1; bad×0 |

| P9 | Test a paged index with hidden records whose fields match the active filter, not only with an empty unauthorized principal. | TRIAL | Three per-record-authorized indexes prove hidden matches cannot affect rows, totals, cursors, or page metadata. | The first application plants one visible and one hidden Change Request, then queries the hidden Environment and its unique search term at limit 1; all four observable page signals remain zero for the hidden record. | The adversarial fixture adds one HTTP test but detects authorization performed after filtering or counting, which a simple empty-result check cannot distinguish. | good×1; bad×0 |

| P10 | Classify outward workflow errors as rollback or committed failure evidence when adding a transaction boundary. | TRIAL | Three multi-operation workflows plant both an error that must roll back and a failure record that must remain visible. | The first PostgreSQL conversion made one existing stale-profile test fail because the transaction rolled back its intended `ExecutionFailed` evidence; the corrected gate now preserves that evidence while an injected audit failure leaves zero approval mutations. | The extra classification branch is narrow and test-backed; it prevents atomicity from erasing operational evidence without weakening fail-closed audit behavior. | good×0; bad×0 |

| P11 | Fence leased decisions with the input revision and recheck current desired authority at proposal dispatch. | TRIAL | Three event-driven workers prove that a concurrent input change produces zero stale proposals or acknowledgements while the newer revision remains runnable. | Before the fence, a worker could load generation N, receive generation N+1, and still delete the stable-key queue row. The PostgreSQL integration now changes the revision during the lease, records the old decision for audit, emits 0 stale outbox rows, and leases N+1 next; the planner also terminally retires a proposal whose desired snapshot changed. | One integer revision and three current-snapshot reads add small database cost, but prevent stale tenant intent from gaining Plan authority without coupling the domain to storage or the legacy facade. | good×1; bad×0 |

For a new PDR, name the method change, trial length, objective exit measure, and
cost dimensions before applying it. Keep one aggregate `good×N` and `bad×N`
tally in the vote cell. Record the underlying observations in the change or an
append-only evidence artifact.
