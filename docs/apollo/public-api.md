The DTOs, strict server interface, and router are generated in
[`internal/apollo/openapi.gen.go`](../../internal/apollo/openapi.gen.go). The
production adapter in
[`internal/controlplane/apollo_openapi_adapter.go`](../../internal/controlplane/apollo_openapi_adapter.go)
implements every generated operation at compile time and preserves identity
checks before request diagnostics.

Conduit-native extensions use `/v1` routes. They are not added to the public
Apollo document or accepted as extra fields by a public `/api/v0` operation.

## Generation pipeline

The next generator must produce one coherent transport package from the pinned
document:

```text
api-definition.yml
  -> request and response DTOs
  -> strict server interface
  -> router bindings
```

The adapter implements that server interface and calls the Apollo application
service directly. Generated types stop in the Apollo context; Catalog and
Environments expose neutral ports and keep their own models. A generated client should be added only
with a supported consumer, so the repository does not ship an unused API.

The generation gate must run offline and compare freshly generated bytes with
the committed output. A route count alone is insufficient because it cannot
detect drift in fields, requiredness, enums, unions, errors, or security
requirements.
